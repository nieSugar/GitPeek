# GitPeek

**GitPeek 是一款面向代码上下文的轻量级 VS Code Git 扩展。** 无需在复杂的 Git 界面间来回切换，即可查看当前代码行的修改者、文件历史、分支变更、选中代码的提交来源，并在提交前审查更改。

## 功能

- **当前行归属**：查看光标所在代码行的作者、日期和提交摘要。文件归属加载后，切换行直接显示缓存结果；当前仓库的 Git 邮箱与提交作者匹配时显示“你”。悬浮提示提供查看提交、查看差异和复制提交 Hash。
- **整文件归属**：按需在每行旁显示作者、日期与提交，支持当前编辑器未保存的内容；新增／修改行标记为未提交，Hover 可打开提交或对应文件 Diff。切换文件后自动退出。
- **文件历史**：浏览文件的近期提交，点击即可查看该文件在本次提交前后的差异，包含重命名历史，并支持加载更多。
- **连续调查**：文件历史可固定当前对象，选择本地／远程分支、标签或提交 Hash，并在该版本中选择其他文件；后退／前进恢复文件、引用、已加载条数和选中的提交。重启后恢复固定历史与提交详情，以及最近 20 个有效调查对象，全程不切换工作区分支。
- **版本导航**：历史 Diff 标题栏可前往上一处／下一处文件修改，保留仓库、重命名前路径与打开时固定的历史快照。
- **提交图**：用分叉连线查看本地和远程提交，显示作者头像、引用与摘要；可从图中查看提交详情，并切换、创建、合并本地分支。
- **整理提交（交互式 Rebase）**：在编辑器内重排当前分支的线性提交，并设置 `pick`、`reword`、`edit`、`squash`、`fixup` 或 `drop`，支持从根提交开始整理；执行前确认计划并保留备份引用，暂停后可继续或中止。
- **Stash**：查看和预览当前仓库临时保存的改动，点击文件直接打开原生 Diff，区分已跟踪和未跟踪快照；预览不应用或删除记录。可保存改动，也可应用或确认删除所选记录。
- **提交详情与差异**：查看提交修改的文件，并在 VS Code 中打开文本差异。二进制文件仅显示元数据，不会作为文本渲染。
- **固定提交详情**：提交详情优先显示摘要、作者与变更文件，多行说明默认折叠，完整 Hash 和路径保留在提示中；标题栏可固定／取消固定，连续打开多个 Diff 无需重复选择提交。
- **历史搜索**：提交图可按消息、作者、Hash 或代码文本变化查询 Git 历史，组合文件／目录路径、起止日期与全部／当前分支范围，并加载更多。代码搜索结果按需列出命中文件，直接打开 Diff 并定位可核实的增删行。路径按字面量匹配；代码变化查找指定文本出现次数改变的提交，日期按本地时区的提交者日期计算，包含起止日。
- **自由比较**：右键提交选择比较起点，再与另一提交比较；历史文件可与当前编辑器内容快照比较，含未保存内容，未打开文件读取磁盘；不保存文件或修改 index。
- **分支比较**：查看当前分支相对基准分支的领先/落后数量、提交、变更文件和差异；标题栏直接选择基准，按仓库记住最近选择，支持配置默认与 `auto`。
- **冲突与恢复**：查看当前 Rebase、Merge、Cherry-pick 等操作和冲突文件，打开原生冲突处理入口；GitPeek 发起的 Rebase 可继续／中止。备份先与当前 HEAD 比较，再创建恢复分支，保留当前分支、index 和工作区。
- **选中代码来源**：按提交归组选中行并统计行数。未提交的行会单独显示，不会打开提交历史。
- **选区演进历史**：追踪选中代码经历过的修改，沿首父提交链处理 Merge，并保留 Git 能识别的重命名前路径；选择提交直接打开对应历史文件的 Diff，历史路径无法确认时查看提交详情。支持编辑中的文本：未修改行映射回 HEAD，混合选区可选择可追溯片段，全新增或改写的行会明确提示。
- **审查更改**：检查已暂存、未暂存和未跟踪的文件及行数，并提示 `console.log`、`debugger`、`TODO`、`FIXME`、`.env` 和 `*.pem` 等内容。
- **文件级暂存**：在更改列表右键暂存或取消暂存文件，支持 Ctrl／Cmd、Shift 多选及分组操作；支持新增、删除、重命名与首次提交，取消暂存保留工作区内容。
- **智能生成提交信息**：根据已暂存文件的名称和状态生成候选信息，并可将所选内容填入当前仓库的 SCM 提交输入框。此功能不使用 AI，也不会检查完整差异来推断意图。

GitPeek 侧栏优先展示紧凑仓库信息和文件历史；提交详情与提交比较在使用时出现，清除比较后收起。分支变更和更改默认折叠，VS Code 会保留你已调整的视图位置与展开状态。针对文件的命令会使用当前活动文件所属的仓库。智能提交通过仓库根目录匹配 VS Code 内置 Git SCM，因此支持多根工作区。

提交图从仓库视图标题栏或命令面板打开。搜索栏默认显示关键词与分支范围，路径和日期放在“高级筛选”中；收起后仍显示条件数量，尚未提交的条件标记为“条件未应用”。比较视图分别显示起点与终点的提交摘要及短 Hash。公开 GitHub 仓库可显示 GitHub 头像；没有公开头像或网络不可用时显示作者首字母。每条提交的操作按钮可复制完整 Hash、检出提交或 Cherry-pick 到当前分支。检出将进入分离 HEAD 状态；检出和 Cherry-pick 均要求工作区干净。Cherry-pick 冲突时可在图中继续或中止。合并分支前也要求工作区干净，发生冲突时保留 Git 的冲突状态供你处理。

## 命令

打开命令面板（`Ctrl+Shift+P` / `Cmd+Shift+P`）运行：

| 命令 | 用途 |
| --- | --- |
| `GitPeek: 文件历史` | 查看当前文件的历史 |
| `GitPeek: 提交图` | 查看提交连线、作者头像和分支操作 |
| `GitPeek: 整理提交（交互式 Rebase）` | 打开当前分支的提交整理编辑器 |
| `GitPeek: 继续 Rebase` | 解决冲突或完成编辑后继续整理 |
| `GitPeek: 中止 Rebase` | 中止正在进行的整理并恢复操作前的状态 |
| `GitPeek: Stash 管理` | 预览、保存、应用或删除 Stash |
| `GitPeek: 查看当前行归属` | 刷新光标所在行的归属信息 |
| `GitPeek: 切换整文件归属` | 在当前编辑器显示或关闭全部行的归属 |
| `GitPeek: 上一处文件修改` | 在历史 Diff 中前往更早的文件修改 |
| `GitPeek: 下一处文件修改` | 在历史 Diff 中前往快照中的更新修改 |
| `GitPeek: 查看选中代码来源` | 查看所选代码行对应的提交 |
| `GitPeek: 选区演进历史` | 沿首父提交链追溯选区的修改 |
| `GitPeek: 与基准分支比较` | 比较当前分支与基准分支 |
| `GitPeek: 查看分支变更` | 查看分支提交和变更文件 |
| `GitPeek: 审查更改` | 检查已暂存、未暂存和未跟踪的更改 |
| `GitPeek: 生成提交信息` | 根据已暂存文件生成候选提交信息 |
| `GitPeek: 刷新` | 刷新 GitPeek 视图和缓存数据 |

文件历史标题栏可固定／恢复跟随当前编辑器、选择历史分支或引用；出现调查轨迹后显示后退／前进按钮。“…”菜单中的“在当前版本中选择文件”可浏览所选快照内的其他文件。选择非 HEAD 引用会自动固定，刷新才读取该引用的新提交；路径不存在时可明确选择其他文件，或继续查看原路径的删除／重命名前历史。

“文件历史”和“与基准分支比较”也可从编辑器标题栏打开。选中文本后，可从编辑器上下文菜单打开“查看选中代码来源”。

右键提交图中的提交，可查看详情、复制完整 Hash、检出、Cherry-pick 或“从此提交开始整理”；检出和 Cherry-pick 保留原有确认与工作区检查。提交图工具栏的“整理提交”可打开当前分支的整理编辑器。右键侧栏的文件历史或分支提交，可查看详情、复制 Hash；文件历史、分支变更文件和更改列表均可右键打开差异。编辑器和资源管理器中的文件也提供“文件历史”和“与基准分支比较”入口，操作使用右键所指文件的仓库。

文件历史、分支变更文件和更改列表还可右键“打开工作区文件”或“复制相对路径”（相对于该文件的仓库根目录）。文件历史中的这些操作使用当前文件路径，历史 Diff 仍使用提交时的路径；工作区文件已删除时会提示，不会创建空文件。四个侧栏视图的标题栏均提供刷新按钮，用于刷新 GitPeek 视图和缓存。

## 设置

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| `gitpeek.enabled` | `true` | 启用 GitPeek 功能。 |
| `gitpeek.blame.enabled` | `true` | 启用当前行归属显示。 |
| `gitpeek.blame.delay` | `100` | 首次加载文件归属前的延迟，单位为毫秒；已缓存的行立即显示。 |
| `gitpeek.history.limit` | `20` | 初次加载的文件历史条数。 |
| `gitpeek.baseBranch` | `auto` | 用于比较的基准分支，或指定分支名称。 |
| `gitpeek.commit.conventional` | `true` | 将智能提交候选信息格式化为 Conventional Commits。 |
| `gitpeek.commit.defaultType` | `chore` | 首选类型：`feat`、`fix`、`refactor`、`perf`、`docs`、`test`、`style` 或 `chore`。 |

## 环境要求

- VS Code **1.96.0 或更高版本**。
- 系统已安装 Git，且 Git 可通过 `PATH` 找到。
- 已启用 VS Code 内置 Git 扩展，以集成 SCM。

## 构建并安装本地 VSIX

在仓库根目录安装开发依赖并构建扩展：

```sh
npm install
npm run check
npm test
npm run package
```

在 VS Code 中安装生成的 VSIX：

```sh
code --install-extension gitpeek-0.7.1.vsix
```

也可以在 VS Code 中运行 **扩展：从 VSIX 安装...**，然后选择生成的文件。

## 自动打包与发布

每次推送分支或创建 Pull Request，GitHub Actions 都会在 Windows 和 Linux 上运行测试、类型检查并生成 VSIX，可从对应 CI 运行的 Artifacts 下载。正式版本安装包见 [GitHub Releases](https://github.com/nieSugar/GitPeek/releases)。

发布新版本时，同步更新 `package.json` 与 `package-lock.json` 的版本号，提交并推送后，为该提交创建相同版本的标签（例如 `v0.7.1`），再推送标签。Release 工作流会检出标签对应的代码，核对版本、运行测试并打包，将同一份 VSIX 附加到 GitHub Release 并发布到 VS Code Marketplace。

Marketplace 首次配置：在 GitHub 仓库 Settings → Secrets and variables → Actions 中添加 `VSCE_PAT` Secret，值为具备 `gitpeek` Publisher 发布权限和 Marketplace → Manage scope 的 Azure DevOps PAT。缺少 Secret 时，商店发布步骤会明确失败。Global PAT 将于 2026-12-01 退役，届时需改用 Microsoft Entra ID 认证，见 [VS Code 官方发布说明](https://code.visualstudio.com/api/working-with-extensions/publishing-extension#secure-automated-publishing-to-visual-studio-marketplace)。

补发历史版本：先将版本标签指向该版本的历史提交并推送，再在 Actions → Release → Run workflow 中选择 `main`，填写对应标签。手动补发不会把旧版设为 Latest；已有同名安装包会保留，默认不发布到 Marketplace。若只需重试某个版本的商店发布，在同一入口勾选 `publish_marketplace`；工作流会重新验证、打包，并跳过商店中已存在的相同版本。

v0.7.0 新增整文件归属、历史版本导航、编辑中选区追溯和交互式 Rebase；v0.7.1 增加连续调查、优化调查布局与行归属响应，并完善本人作者显示和悬浮操作。历史版本 v0.1.0～v0.6.0 使用各自验收提交补发。

## 范围与限制

GitPeek 0.7.1 包含历史筛选、连续调查、整文件归属、版本导航、编辑中选区追溯和交互式 rebase。Pull Request 集成、AI 聊天、按行暂存及丢弃修改仍不在范围内。智能提交仅根据已暂存文件的路径和状态提供措辞建议，提交前请检查生成的信息。二进制差异仅显示元数据，不显示文件内容。

窗口内调查轨迹最多保留 50 个对象；重启时恢复包含当前固定对象的最多 20 个有效调查对象，其余临时轨迹不恢复。历史 Diff 按打开时的快照导航；无法可靠对应到当前工作区的历史文件仅提供历史内容，不猜测同名文件。

代码变化搜索使用 Git `-S`，区分大小写；同一文本只改变位置而出现次数不变时不会命中。路径筛选只匹配填写的文件或目录，不跨重命名前路径追踪；追踪重命名请使用文件历史。

两个提交采用快照 A → B 直接比较；“与基准分支比较”仍使用共同祖先 → HEAD。当前文件比较捕获发起操作时的编辑器文本，后续编辑不会改变已打开的快照。代码搜索定位只采用补丁中的可核实增删行，二进制或跨未变化行的命中会明确说明无法定位。选区历史沿 Git 首父提交链追踪，Merge 显示合入结果，不展开其他父链；复制或大幅改写导致 Git 无法识别的重命名可能中断追踪。编辑中的选区只追溯与 HEAD 对应的未修改片段；整文件归属和编辑中追溯支持 2 MB、20,000 行以内的文本。版本导航固定在打开时的历史快照，重新打开文件历史 Diff 才包含新提交。

调查恢复仅保存仓库、固定 Hash、路径、分页（最多 2,000 条）和选中提交，不保存文件内容。仓库、提交或文件失效时提示重新选择；恢复后的历史使用保存时的提交快照，取消固定可继续跟随当前分支。切换查询条件、仓库或关闭相关视图会取消过期只读查询，Git 写操作不随之取消。

更改列表支持 Ctrl／Cmd 多选和 Shift 连选。暂存可混选同一仓库的未暂存与未跟踪文件；取消暂存只接受已暂存文件。右键分组或点击分组的加／减按钮可处理当前分组，文件行也提供快捷按钮。所选文件中有冲突、未保存修改或过期状态时整批停止；操作只更新 index，不删除磁盘文件。

交互式 rebase 使用原生 Git，每次最多整理当前分支的 200 个线性提交（可包含根提交），不重写 Merge 历史，不支持跨分支 `onto`，也不会自动推送。开始前要求工作区干净且没有未保存文件；所选历史被本地远程跟踪引用包含时，会特别提示历史重写风险。本地未发现远程引用不能证明提交从未推送。执行前在 `refs/gitpeek/rebase/` 下保留原 HEAD 的备份引用，完成或中止后仍保留，可用于恢复。

发生冲突时，先解决并暂存文件，再执行“继续 Rebase”；选择 `edit` 暂停后，手动修改并通过 `git commit --amend` 完成该提交，再继续。中止会丢弃本次 rebase 产生的冲突改动并恢复操作前状态。

“查看当前操作与冲突”可检查其他工具发起的操作，但 GitPeek 不接管外部 Rebase。“比较与恢复 Rebase 备份”创建一个新分支指向备份，不自动检出、重置或推送。

大仓库基线：`npm run benchmark:large -- 20000 3` 在 `.vscode-test/large-benchmark/` 生成隔离仓库和 VS Code 配置，测量当前提交图从数据查询到 Webview 绘制的耗时、资源样本，以及长文件历史和分支比较的数据查询；可传第 3 参数指定 VS Code 可执行文件。环境、范围和结果见 [改进计划](docs/GitPeek-Improvement-Plan.md)。

关闭面板或重启 VS Code 后，可再次执行“整理提交”恢复 GitPeek 发起的 rebase；其他工具发起的 rebase 仍由原工具处理。完成后如需找回原历史，可使用面板显示的备份引用创建恢复分支：`git branch <恢复分支名> <备份引用>`，再检查原有提交。备份引用不会自动删除。
