# GitPeek 代码调查体验改进方案

根据 [GitPeek 与 GitLens 对比](./GitPeek-GitLens-Comparison.md)，本轮以 0.6.0 为基线，优先改善连续调查代码时的上下文、搜索范围与结果准确性。原始对比记录保留；本方案根据 2026-10-08 用户的执行请求立项。

## 改进任务与验收

| 优先级 | 改进 | 实施范围 | 验收标准 | 状态 |
| --- | --- | --- | --- | --- |
| P0 | 连续历史调查保留上下文 | 文件历史显示仓库、文件和当前比较对象；Diff 明确左右版本；选区历史在历史路径已知时直接打开文件 Diff | 连续切换提交、跨重命名和多仓库时，文件身份与比较对象保持准确；原有点击即 Diff 保留 | 已完成 |
| P0 | 历史搜索增加筛选 | 复用提交图与系统 Git，增加文件路径、代码文本变化及日期范围，沿用分支范围和分页 | 中文及特殊字符按字面量处理；组合筛选、加载更多、清除、错误恢复一致 | 已完成 |
| P0 | 分支比较使用一致快照 | 比较前固定基准与 HEAD 的提交；补齐引用变化监听和过期结果检查 | 分支或基准移动时不混用文件、统计和 Diff；Windows、多仓库与远程引用检查通过 | 已完成 |
| P1 | 性能测量可复现 | 提供只读基线脚本，记录环境、提交、数据查询延迟与 Git 调用量 | 同一仓库可重复运行，明确测量范围，不据此宣称比 GitLens 更快 | 已完成 |

## 本轮边界

- 沿用原生 VS Code Diff、TreeView 和现有提交图，不增加运行时依赖。
- 选区追溯继续沿首父链；不能确认历史路径时打开提交详情，不猜测文件身份。
- 代码变化搜索采用 Git `-S`，查找指定字面文本出现次数变化的提交，不代表完整语义搜索。日期使用提交者日期，界面明确时区。
- PR 集成、交互式 rebase、整文件 blame 和跨父链选区追踪仍为后续候选，不在本轮实现范围内。

## 性能复测

```sh
npm run benchmark -- . README.md HEAD~1 10
```

参数依次为仓库、仓库内文件、比较基准与重复次数。脚本只读取目标仓库，在系统临时目录构建测量代码。每项先运行一次，再记录后续重复运行的 P50、P95、最小及最大延迟、每轮 Git 调用数与输出字节数。

测量覆盖文件历史、当前行 blame、提交图、消息搜索、文件 Diff 内容和分支比较的数据层；不包含 VS Code 渲染、用户点击耗时、Git 子进程资源占用或 GitLens 同机对照。首次观察值不等于冷缓存性能。
