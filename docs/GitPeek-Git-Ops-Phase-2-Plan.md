# GitPeek Git 操作第二阶段计划（草案）

- 基线：`v0.2.0` 已交付提交图、公开 GitHub 头像，以及本地分支切换、创建、合并。
- 阶段目标：从提交图直接完成常用的提交级操作，并清楚展示操作结果与冲突状态。
- 来源：本轮用户选择的“先做分支操作”和现有代码；待用户提供所指的 MCP 任务源后逐项对齐。旧版 [v0.1.0 开发计划](./GitPeek-Development-Plan.md)中的“阶段 2”是已完成的 Current Line Blame。
- 执行约定：每个功能及其自动检查各占一个 Conventional Commit；按可并行的代码边界交给 `6luna` 子代理，最后统一集成与实际 UI 验收。

## 任务 2.1：提交图操作入口与复制 Hash

- 在提交行提供可用键盘操作的菜单或按钮，保持点击行查看 Commit Detail 的现有行为。
- 复用现有“复制 Commit Hash”能力，把所选提交的完整 Hash 写入剪贴板并给出反馈。
- 仅接受当前图快照中存在的 Commit Hash，切换仓库或刷新后不沿用旧选择。
- 验收：鼠标和键盘均可复制完整 Hash；多仓库切换后操作指向当前仓库。
- 独立提交：`feat(graph): 添加提交操作入口与复制 Hash`。

## 任务 2.2：检出提交

- 从提交行执行 `git switch --detach <hash>`；执行前显示目标短 Hash 与分离 HEAD 提示。
- 工作区有暂存、未暂存或未跟踪更改时停止操作并提示先处理更改。
- 成功后刷新提交图、仓库视图、当前行归属和分支比较；保留 Git 的原始错误信息。
- 验收：真实临时仓库中成功进入分离 HEAD；取消确认或工作区不干净时 HEAD 不变。
- 独立提交：`feat(commit): 支持从提交图检出提交`。

## 任务 2.3：Cherry-pick

- 从提交行将普通提交应用到当前分支；分离 HEAD、工作区不干净或选中 Merge Commit 时明确拒绝。
- 操作前确认目标提交与当前分支；冲突时保留 Git 状态，在界面提供“继续”和“中止”入口，不自动丢弃改动。
- 成功、继续或中止后刷新提交图和相关上下文；错误提示包含下一步处理信息。
- 验收：真实仓库覆盖成功、冲突后继续、冲突后中止、取消确认及脏工作区；各路径不会误操作其他仓库。
- 独立提交：`feat(commit): 添加 Cherry-pick 与冲突处理`。

## 依赖与并行边界

1. 先确定任务 2.1 的 Webview 消息格式和提交选择校验；之后任务 2.2、2.3 的 Git 操作与真实仓库检查可并行实现。
2. 两个操作都通过现有 `GitService.run` 执行参数数组，不拼接 shell 命令；UI 集成由主代理统一完成，避免同时修改提交图视图。
3. 集成后运行 `npm run check`、`npm test`、`npm run package`，并在 VS Code 测试仓库验证菜单、确认、刷新与错误状态。

## 本阶段之外

Stash、Reset、Interactive Rebase、远程 Push/Pull 和 PR 集成留待后续单独划分；这些操作需要各自的状态恢复与验收规则。
