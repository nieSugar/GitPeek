# GitPeek 深入代码调查改进方案

本轮承接 [第一轮改进](./GitPeek-Improvement-Plan.md)，落实 2026-10-08 资深用户对比后提出的三个方向：整文件归属、前后版本导航，以及编辑代码时继续追溯历史。三项功能共用系统 Git 和 VS Code 原生编辑器，不增加运行时依赖。

## 任务与验收

| 优先级 | 改进 | 实现方式 | 验收条件 | 状态 |
| --- | --- | --- | --- | --- |
| P0 | 整文件归属 | 编辑器右键或命令面板切换行旁标注；显示作者、日期、提交，Hover 可开详情或 Diff | 编辑器未保存文本也可查询；未提交行单独标记；编辑后清除旧结果；切文件、禁用、关闭时释放标注及监听 | 已完成 |
| P0 | 前后版本导航 | 原生历史 Diff 标题栏增加上一处和下一处修改；按打开时固定的历史快照导航 | 重命名仍打开正确路径；根提交／最新修改给边界提示；双侧编辑器、多仓库、HEAD 移动和并发点击不串版本 | 已完成 |
| P0 | 编辑中选区追溯 | 将编辑器快照中的未修改片段映射至 HEAD 行号，再查询选区演进 | 上方插入／删除行、其他位置修改、未保存、已暂存重命名均可追溯；混合选区让用户选择可追溯片段；不保存文件、不改 index | 已完成 |

## 使用入口

- 编辑器右键或命令面板：`GitPeek: 切换整文件归属`。再次执行关闭；切换文件也会退出。开启时暂停原有单行标注，退出后恢复。
- GitPeek 的提交文件 Diff：标题栏箭头或命令面板中的 `GitPeek: 上一处文件修改`、`GitPeek: 下一处文件修改`。
- 选中编辑器代码：`GitPeek: 选区演进历史`。未保存修改不再阻断整个文件的追溯；若选区包含改写内容或不连续的 HEAD 范围，先选择保留的片段。

## 准确性边界

- 整文件归属读取当前编辑器文本，使用 Git 的归属及内容转换规则。真正新增或修改的行不会显示成旧提交。
- 选区映射只认可 Git 文本差异中的未修改行，统一 CRLF／LF 行尾。不推断重写或移动代码的语义来源；全新增／改写片段给出明确说明。
- 已暂存且可被 Git 识别的重命名可映射到 HEAD 的旧路径；未经 Git 识别的新路径不猜测来源。
- 选区历史与版本导航仍沿首父提交链。版本导航固定在打开 Diff 时的提交快照；要包含之后的新提交，重新从文件历史打开 Diff。
- 整文件归属与编辑中选区追溯限制为 2 MB、20,000 行以内的文本文件。Git 查询有超时和输出大小限制。
- PR 平台集成、跨父链追踪与语义级代码迁移识别保留为后续范围，本轮不添加账号、远程服务或依赖。
